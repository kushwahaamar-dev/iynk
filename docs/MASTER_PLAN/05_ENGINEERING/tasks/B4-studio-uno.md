## 3. Conventions every B4 task obeys

Everything in `IMPLEMENTATION_ROADMAP.md` section 2 applies. The shorthands `TL`, `V <path>`, `E <spec>`, `KL`, `BUILD` are defined there (2.3). Added here:

| Name | Expands to |
|---|---|
| `PORT` | `npx tsc -p tsconfig.portable.json` (T-B2-01). Run by any task that adds a file under `src/project` or `src/parts`. |
| `ARCH` | `npx vitest run src/architecture.test.ts` (T-B2-01): the import matrix. Run by every task that adds an import across a module boundary. |
| `I18N` | `npx vitest run src/i18n/messages.test.ts` |
| `COMMIT` | One commit for the task, message `B4 T-B4-nn: <what>`, author Amar Kushwaha, no `Co-Authored-By`, no "Generated with" line, never pushed. |

| Rule | Detail |
|---|---|
| Module boundaries | `src/studio/**` is browser code but pure logic stays DOM-free so it tests in Node. `src/studio` imports `src/project`, `src/parts`, `src/core`; never `src/local`, `src/sim-host`, `src/collab`, `src/ai` (FRONTEND 5.3). React code is in `src/components/studio/**`. Joins to storage and the sim host are in `src/components/studio/wiring/`, the only place in `components/studio` that imports `src/local` and `src/sim-host`. |
| Tools never write | A `Tool` returns `ToolResult`; only the tool host calls `DocStore.commit` (STUDIO 0 row 3, ADR-0802). A grep test (`src/studio/no-direct-writes.test.ts`, owned by T-B4-04) fails on any `session.apply(` or `ProjectSession` mutator call (`undo`, `redo`, `replace`) outside `stores/doc.ts`. It skips `*.test.ts` and `*.test.tsx` files and does not match a bare `.apply(` (that also matches `Function.apply` and `Reflect.apply`). |
| Op names | Exactly those of `PROJECT_DATA_MODEL.md` 7.2 (`k` discriminator, 64 kinds). Reject codes are the closed list in 7.2. |
| Units and ids | mm, rotation in degrees (multiples of 90 in the breadboard view), ids `cmp_`, `brd_`, `net_`, `wir_`, `vw_`, `src_`, `prj_` from the id generator of T-B2-02. Positions are quantised at write by `apply` (PDM 4.2). |
| Text is text | Part names, labels, refdes, file names and serial output are rendered as text nodes or SVG `<text>`, never `dangerouslySetInnerHTML`. A lint test (`src/studio/no-html-injection.test.ts`, T-B4-24) greps `src/studio` and `src/components/studio` for `dangerouslySetInnerHTML` and `innerHTML`, skipping `*.test.ts` and `*.test.tsx` files (including itself, whose source names both words). |
| Colour is never the only cue | Every state drawn in colour carries an outline, glyph or text tag (R-070, UX section 12). |
| No network | Studio makes no request outside the app origin on the M1 path (M1 step 1). |
| CSP | B1's CSP stays at 0 violations on `/en/studio`. No inline script, no `eval`, workers from `'self'`. T-B4-22 listens for `securitypolicyviolation`. |
| Next.js | 16.4.3. Before naming a Next API the agent reads the guide named in the task. `ssr: false` is allowed only inside a Client Component (`node_modules/next/dist/docs/01-app/02-guides/lazy-loading.md:66` and `:94`, VERIFIED). |
| i18n | A UI string is a key in a Studio namespace in all six languages in the same commit (K-I18N). Plain words. No "validated". No em dashes. |
| A task that cannot finish | Stops, reports, does not widen. |
| UI (refresh, BU) | Every task that renders anything a person sees reads `/Users/amar/iynk-build/state/UI_RULES.md` and `docs/UI.md` first, builds from `src/components/ui` (import from `@/components/ui`; `Icon` for icons; `Panel`, `Tabs`, `Sheet`, `Popover`, `Menu`, `Dialog`, `EmptyState`, `Skeleton`, `SegmentedControl`, `Toggle`, `Chip`, `Kbd` exist) and passes `npm run ui:check` (part of `npm run check`). Screenshots are taken as UI_RULES says. |
| Timing budgets (refresh, MF) | A wall-clock assertion under 1 s goes in a `*.perf.test.ts(x)` file: `npm run test` excludes those and `npm run test:perf` runs them one file at a time (`vitest.perf.config.mts`). A timing in a unit test file is recorded or asserted loosely, never at the card's tight figure. Playwright timings go in the `perf` project (T-B4-05). |
