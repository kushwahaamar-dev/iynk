# Reconciliation of the design documents

Status: arbiter ruling, 2026-10-27. Written before the build plan. Binding where two design documents disagree.
Scope: this file decides. It does not edit the other documents. A fixer applies each row to the files it names.
Method: seven sweeps listed disagreements. Each was re-checked against the files named below. Items that were already fixed or were wording only are in "Dropped".

## Precedence used

| Rule | Meaning |
|---|---|
| R1 | DECISION_REGISTER D-013 to D-017 and the kept D-007, D-010, D-011 |
| R2 | A measured spike result (REPORT.md and its number) |
| R3 | The ADR that owns the topic, per ADR/README.md |
| R4 | The owning document: schemas and PROJECT_DATA_MODEL (PDM) own fields; API_CONTRACTS with openapi.yaml own routes; SYSTEM_ARCHITECTURE owns modules and storage; SIMULATION_ARCHITECTURE (SIM) owns cause ids; FEATURE_CATALOGUE owns F-ids |
| R5 | Otherwise the simpler, safer, more reversible option, labelled PROPOSAL |

Short names: REG = DECISION_REGISTER, PRD = PRODUCT_REQUIREMENTS, FP = FEATURE_PRIORITIZATION, FC = FEATURE_CATALOGUE, UJ = USER_JOURNEYS, BE = BACKEND_ARCHITECTURE, RT = REALTIME_ARCHITECTURE, SYS = SYSTEM_ARCHITECTURE, DG = SYSTEM_DIAGRAMS, FE = FRONTEND_ARCHITECTURE, API = API_CONTRACTS, CS = COMPONENT_SCHEMA, STU = STUDIO_EDITOR, COM = COMMUNITY, EDU = EDUCATION, ROB = ROBOTICS_ARCHITECTURE, DRN = DRONE_ARCHITECTURE, UX = UX_DESIGN_SYSTEM. ADR files are in `04_ARCHITECTURE/ADR/`.

Note on D-018 to D-021: they are "Decided by orchestrator, Amar may overrule". They are not R1. Where a row departs from one, it is listed under "For Amar".
