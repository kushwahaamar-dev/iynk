# MPU-6050 on a GY-521 breakout: fact sheet

Status: written 2026-10-24 between 13:54 and 14:10 CDT. Values marked **(unverified)** could not be checked against a primary source in the time box. Values marked **(estimated from photo [7])** were measured from a photograph, not from a design file.

## 0. Header

- **Chip modelled:** TDK InvenSense **MPU-6050**, 6-axis MEMS MotionTracking device (3-axis gyroscope + 3-axis accelerometer + Digital Motion Processor, DMP), 24-pin QFN, 4 × 4 × 0.9 mm [1]. Datasheet: Product Specification PS-MPU-6000A-00 (read: Rev 3.1, 10/24/2011; the last release is Rev 3.4, 08/19/2013) [1]. Register map RM-MPU-6000A-00 (read: Rev 4.0, 03/09/2012; last release Rev 4.2) [2]. The values used below did not change between the revision read and the last one, as far as checked **(unverified for 3.4/4.2 specifically: the TDK site returned a bot-check page instead of the PDFs)**.
- **Board modelled:** **GY-521**, a generic, unbranded Chinese breakout. There is no manufacturer, no part number and no official design file. Several PCB variants exist (section 2.1). The only schematic in circulation is "MPU6050-V1-SCH" (Arduino Playground) [3].
- **What it is:** a small blue PCB (about 15.6 × 20.3 mm) that carries the MPU-6050, a 3.3 V LDO so it can be powered from 5 V, I²C pull-up resistors, a pull-down on AD0 (address 0x68), a power LED, decoupling capacitors and an 8-pin 2.54 mm header (VCC, GND, SCL, SDA, XDA, XCL, AD0, INT). The host reads raw 16-bit gyro and accelerometer values over I²C (up to 400 kHz) and does any sensor fusion itself (or uploads InvenSense's DMP firmware). It measures rotation **rate**, not angle: angle comes from integrating the gyro (drifts) and/or from the accelerometer's gravity vector (noisy, upset by any linear acceleration).
- **Lifecycle (as of October 2026):** the MPU-6050 is **NRND / discontinued**. Distributors list it as "Not For New Designs" / "NRND" / "Discontinued" / "No Longer Available" (Cytech, LionCircuits, CDI, Newark, Farnell) [9]. TDK's own product page now returns 404, and no official TDK PCN/EOL notice naming the MPU-6050 was found (TDK's 2021 motion-device EOL notice PCN-000501 lists the MPU-3050 and MPU-9350, not the MPU-6050); a TDK support-forum thread is titled "MPU 6050 not for new design" (https://adm.invensense.tdk.com/mpu-6050-not-new-design, now 404). So: **NRND per TDK's forum and distributors; formal EOL date unknown (unverified)**. Its evaluation board EV_MPU-6050 is listed by DigiKey as "Obsolete" [9]. TDK's current replacements are the ICM-42670-P / ICM-42688-P family **(unverified which one TDK names as the official successor)**. GY-521 boards are still sold in huge numbers, and many now carry recycled, remarked or clone chips (section 6).

### 2.2 Frame

The usual reading orientation (the eight pin labels, the chip marking and the axis arrows are readable) is **portrait, with the header along the LEFT edge and VCC at the top** [7][5]. Origin = bottom-left corner. +x right, +y up (away from the viewer), mm. **The bottom edge is the short edge next to the INT pin.** The right edge carries the two mounting holes and the vertical "ITG/MPU" text.

To lay the board header-to-the-front (as the original sim did, 21 × 16): rotate by −90° about the origin (x' = y, y' = 15.6 − x); then VCC is at the left, INT at the right, holes at the back.

- Pin labels, horizontal, just right of each pad, in order top to bottom: `VCC`, `GND`, `SCL`, `SDA`, `XDA`, `XCL`, `AD0`, `INT` (label left edge at x ≈ 2.6, cap height ≈ 1.2 mm).

## 3. Electrical

### 3.1 MPU-6050 core [1][2]

| Item | Value |
|---|---|
| Sensors | 3-axis MEMS vibratory gyroscope (Coriolis, capacitive pick-off) + 3-axis MEMS accelerometer (one proof mass per axis, capacitive) + temperature sensor; six 16-bit ADCs, sampled simultaneously |
| DMP | Digital Motion Processor (sensor fusion firmware uploaded by the host, e.g. I2Cdevlib's `MotionApps`), 1024-byte FIFO |
| Clock | internal 8 MHz oscillator (±1 % over temperature on the timing generator), or PLL locked to a gyro axis (recommended; CLKSEL = 1), or external 32.768 kHz / 19.2 MHz on CLKIN (tied to GND on GY-521) |
| Interface | I²C slave, up to 400 kHz fast mode. Address `0b110100X`: **0x68** with AD0 low (GY-521 default via 4.7 kΩ pull-down), **0x69** with AD0 high. (MPU-6000 also has SPI; the MPU-6050 does not.) |
| Aux I²C | XDA/XCL = AUX_DA/AUX_CL: the chip's own I²C **master** for an external magnetometer; can be put in pass-through (bypass) mode via INT_PIN_CFG.I2C_BYPASS_EN. Not the host bus. |
| VDD | 2.375-3.46 V (GY-521: 3.3 V from the LDO) |
| VLOGIC | 1.71 V to VDD (GY-521: tied to VCC_3.3V) |
| Current | 3.9 mA gyro + accel + DMP; 3.8 mA gyro + accel; 3.6 mA gyro only; 500 µA accel only; accel low-power 10 µA @ 1.25 Hz … 110 µA @ 40 Hz; full-chip idle (sleep) 5 µA |
| Start-up | register R/W available 20 ms typ, 100 ms max after power; gyro ZRO settling to ±1 °/s of final: 30 ms |
| Power-on state | **asleep**: PWR_MGMT_1 = 0x40 (SLEEP = 1). Outputs read 0 until the host clears SLEEP. |

### 3.2 Ranges and sensitivities [1][2]

| GYRO_CONFIG FS_SEL (bits 4:3) | Range | Sensitivity | | ACCEL_CONFIG AFS_SEL (bits 4:3) | Range | Sensitivity |
|---|---|---|---|---|---|---|
| 0 | ±250 °/s | **131 LSB/(°/s)** | | 0 | ±2 g | **16384 LSB/g** |
| 1 | ±500 °/s | 65.5 | | 1 | ±4 g | 8192 |
| 2 | ±1000 °/s | 32.8 | | 2 | ±8 g | 4096 |
| 3 | ±2000 °/s | 16.4 | | 3 | ±16 g | 2048 |

Outputs are signed 16-bit two's complement, big-endian (high byte first). Gyro scale-factor tolerance −3 to +3 % at 25 °C, variation over temperature ±2 %, nonlinearity 0.2 %, cross-axis ±2 %. Accel initial calibration tolerance ±3 %, nonlinearity 0.5 %, cross-axis ±2 % [1]. Both are factory calibrated [1].

Temperature: `T(°C) = TEMP_OUT / 340 + 36.53` (TEMP_OUT signed) [2]; sensitivity 340 LSB/°C, offset −521 LSB at 35 °C, range −40 to +85 °C [1]. It is the **die** temperature, a few °C above ambient.

### 3.3 Bias, drift, noise [1]

| Parameter | Value (FS_SEL = 0 / AFS_SEL = 0, 25 °C) |
|---|---|
| Gyro initial zero-rate output (ZRO) tolerance | **±20 °/s** |
| Gyro ZRO variation −40 to +85 °C | ±20 °/s |
| Gyro total RMS noise (DLPF_CFG = 2, 100 Hz) | **0.05 °/s rms** |
| Gyro low-frequency noise 1-10 Hz | 0.033 °/s rms |
| Gyro rate noise spectral density @ 10 Hz | **0.005 °/s/√Hz** |
| Accel zero-g initial tolerance | **±50 mg X/Y, ±80 mg Z** |
| Accel zero-g change 0-70 °C | ±35 mg X/Y, ±60 mg Z |
| Accel noise power spectral density @ 10 Hz | **400 µg/√Hz** |

What this means for the simulation:
- An uncalibrated gyro at rest reads a constant bias that can be anything inside ±20 °/s (spec limit); a few °/s is common in practice **(typical value unverified)**. Integrated, a bias b gives an angle error growing at b °/s: 2.4 °/s (the original's value) is realistic for an uncalibrated unit. After averaging ~500-1000 samples at rest and subtracting, the residual is about 0.01-0.1 °/s, and it wanders with temperature (warm-up after power-on changes it) **(typical figures unverified)**.
- White noise: at 0.005 °/s/√Hz the integrated-noise angle random walk is 0.005 × 60 = 0.3 °/√h, negligible next to bias.
- Raw counts at rest (±250 °/s): noise 0.05 °/s × 131 ≈ ±7 LSB rms; a 2 °/s bias reads ≈ 262 LSB. Accel at rest flat: Z ≈ +16384 (±80 mg offset → ±1300 LSB), X/Y ≈ 0 (±50 mg → ±820 LSB); noise 400 µg/√Hz × √(44 Hz × 1.57) ≈ 3.4 mg rms ≈ 55 LSB at DLPF 44 Hz (computed).
- Accelerometer tilt noise when still: 3.4 mg rms ≈ 0.2° rms. The large "jumps" when hand-held are real linear accelerations (bumps), not sensor noise.

### 3.4 Key registers [2]

| Addr | Name | Reset | Use |
|---|---|---|---|
| 0x19 (25) | SMPLRT_DIV | 0x00 | Sample Rate = Gyro Output Rate / (1 + SMPLRT_DIV). Gyro output rate = **8 kHz** with DLPF_CFG = 0 or 7, **1 kHz** otherwise. Accel output is always 1 kHz. Example: DLPF_CFG = 3, SMPLRT_DIV = 9 → 100 Hz. |
| 0x1A (26) | CONFIG | 0x00 | bits 5:3 EXT_SYNC_SET, bits 2:0 **DLPF_CFG** (table below) |
| 0x1B (27) | GYRO_CONFIG | 0x00 | bits 7:5 self-test X/Y/Z, bits 4:3 FS_SEL |
| 0x1C (28) | ACCEL_CONFIG | 0x00 | bits 7:5 self-test, bits 4:3 AFS_SEL |
| 0x23 (35) | FIFO_EN | 0x00 | which data go to the FIFO |
| 0x37 (55) | INT_PIN_CFG | 0x00 | INT_LEVEL (0 = active high), INT_OPEN (0 = push-pull), LATCH_INT_EN (0 = a **50 µs pulse**), INT_RD_CLEAR (0 = status cleared only by reading INT_STATUS), FSYNC bits, I2C_BYPASS_EN (bit 1: host reaches XDA/XCL devices directly when I2C_MST_EN = 0) |
| 0x38 (56) | INT_ENABLE | 0x00 | DATA_RDY_EN (bit 0), FIFO_OFLOW, I2C_MST |
| 0x3A (58) | INT_STATUS | 0x00 | DATA_RDY_INT (bit 0); cleared when read (default) |
| 0x3B-0x40 | **ACCEL_XOUT_H** … ACCEL_ZOUT_L | — | 6 bytes, X/Y/Z, high byte first |
| 0x41-0x42 | TEMP_OUT_H/L | — | temperature |
| 0x43-0x48 | **GYRO_XOUT_H** … GYRO_ZOUT_L | — | 6 bytes |
| 0x6A (106) | USER_CTRL | 0x00 | FIFO_EN, I2C_MST_EN, resets |
| 0x6B (107) | **PWR_MGMT_1** | **0x40** | bit 7 DEVICE_RESET, bit 6 SLEEP, bit 5 CYCLE, bit 3 TEMP_DIS, bits 2:0 CLKSEL (0 = 8 MHz internal, 1/2/3 = PLL on gyro X/Y/Z, 4 = ext 32.768 kHz, 5 = ext 19.2 MHz, 7 = stop). Write **0x00** to wake (Playground) or **0x01** to wake with the gyro-X PLL (Adafruit, recommended). |
| 0x6C (108) | PWR_MGMT_2 | 0x00 | LP_WAKE_CTRL, per-axis standby |
| 0x72-0x74 | FIFO_COUNT_H/L, FIFO_R_W | — | FIFO |
| 0x75 (117) | **WHO_AM_I** | **0x68** | bits 6:1 = 110100; bits 0 and 7 read 0. **AD0 does not change it: a chip at 0x69 still answers 0x68.** |

### 3.5 Power tree (GY-521) [3]

- **VCC pin** → LDO input (with C3 4.7 µF to GND) → **VCC_3.3V** (10 µF + 0.1 µF) → MPU-6050 VDD (0.1 µF C102) and VLOGIC (10 nF C11), the LED and the pull-ups. REGOUT has 0.1 µF (C13) and CPOUT 2.2 nF (C14), as the datasheet's typical circuit requires (C1 0.1 µF X7R, C2 0.1 µF, C3 2.2 nF 50 V, C4 10 nF) [1].
- On the V1 schematic the LDO EN pin is tied to its input (always on); "by" (bypass/noise cap) is unconnected **(as drawn)**.
- **No reverse-polarity diode, no fuse, no level shifter, no ESD parts.**
- **662K = XC6206P332MR** (Torex; many second sources, e.g. UMW) [10]: fixed 3.3 V, SOT-23-3. Torex family figures (datasheet excerpt [14]): maximum operating input **6.0 V**, output current 250 mA (5.0 V type), dropout **250 mV @ 100 mA** (3.0 V type), SOT-23 dissipation 250 mW. UMW second source: VIN max 8 V, 100 mA, dropout 0.24 V max @ 50 mA [10]. Pinout ("MR" = SOT-23) 1 = VSS, 2 = VOUT, 3 = VIN **(from memory: unverified)**; quiescent current ≈ 1 µA **(unverified)**; current limiter / short-circuit protection **(unverified)**; no thermal shutdown **(unverified)**. Dissipation check: (5 − 3.3) V × 5 mA = 8.5 mW, trivial.
- Total board current: MPU-6050 ≈ 3.9 mA + LED ≈ 1.3 mA ((3.3 − ~2.0 V)/1 kΩ, computed) + LDO quiescent ≈ **5 mA**.
- **VCC range:** about 3.5-5.5 V on a 662K board (3.3 V + ~0.1 V dropout at 5 mA, to the 6 V abs max of the Torex part). Feeding 3.3 V into VCC works on most boards (the MPU then sees ~3.2 V, still inside 2.375-3.46 V) but the Playground warns the result "might be too low" on some regulators and recommends 5 V [4].

### 3.6 Logic levels and the 5 V question

- The pull-ups go to **VCC_3.3V** (the LDO output), not to VCC [3]. So on a 5 V Arduino Uno/Nano, SDA and SCL idle at 3.3 V. The AVR's VIH min is 0.6 × 5 V = 3.0 V, so 3.3 V reads high (thin 0.3 V margin) and the bus works without a level shifter in practice. The AVR core's `Wire.begin()` turns on the ATmega's internal pull-ups (`twi.c`: "activate internal pullups for twi", `digitalWrite(SDA, 1)`), 20-50 kΩ to 5 V, in parallel with the board's 4.7 kΩ to 3.3 V: the idle level rises to about 3.3 + 1.7 × 4.7/(4.7+35) ≈ 3.5 V (computed with 35 kΩ), under the 3.8 V abs max, and the extra current into the chip is negligible.
- MPU-6050 digital inputs (SCL, SDA, AD0, INT, FSYNC, AUX) absolute max = **VDD + 0.5 V = 3.8 V** [1]. They are **not 5 V tolerant**. Wiring **AD0 to the Arduino's 5 V** (a common way to select 0x69) exceeds that: use 3.3 V for AD0 high. The pull-ups on SDA/SCL to 5 V (e.g. another module's 10 kΩ to 5 V) also exceed it.
- VIH = 0.7 × VLOGIC (2.31 V), VIL = 0.3 × VLOGIC (0.99 V), at VLOGIC = 3.3 V [1].
- INT: push-pull (default) or open-drain output, active high by default, 3.3 V high level [2].
- Bus capacitance ≤ 400 pF [1]. Two GY-521s in parallel: 4.7 k ∥ 4.7 k = 2.35 kΩ (fine); with 2.2 kΩ boards, two in parallel give 1.1 kΩ, and the sink current at 3.3 V ≈ 3 mA (I²C fast-mode limit 3 mA), so it is marginal.

Raw Wire (no library), from the Playground pattern [4] plus register map [2]:

```cpp
#include <Wire.h>
const uint8_t MPU = 0x68;               // AD0 low

int16_t read16() {                       // high byte first
  uint8_t hi = Wire.read();
  uint8_t lo = Wire.read();
  return (int16_t)((hi << 8) | lo);
}

void setup() {
  Serial.begin(115200);
  Wire.begin();
  Wire.setClock(400000);
  Wire.beginTransmission(MPU);
  Wire.write(0x6B);                      // PWR_MGMT_1
  Wire.write(0x01);                      // wake up, clock = PLL on gyro X
  Wire.endTransmission();
}

void loop() {
  Wire.beginTransmission(MPU);
  Wire.write(0x3B);                      // ACCEL_XOUT_H
  Wire.endTransmission(false);           // repeated start
  Wire.requestFrom(MPU, (uint8_t)14);
  int16_t ax = read16(), ay = read16(), az = read16();
  int16_t t  = read16();
  int16_t gx = read16(), gy = read16(), gz = read16();
  Serial.print(ax / 16384.0); Serial.print(' ');   // g at +-2 g
  Serial.print(gy / 131.0);   Serial.print(' ');   // deg/s at +-250 deg/s
  Serial.println(t / 340.0 + 36.53);               // deg C
  delay(10);
}
```

Write the two reads as separate statements: `Wire.read() << 8 | Wire.read()`, common in tutorials, leaves the order of the two calls unspecified in C++ (it works on avr-gcc in practice).

Console: there is no upload to the module itself; the host's upload messages apply (see the host board's fact sheet). An I²C scanner prints `I2C device found at address 0x68  !` (the classic Arduino I2C scanner wording) **(scanner wording varies by sketch)**. If a 6-byte read returns all zeros, the chip is still asleep (PWR_MGMT_1 not written). If it returns all 0xFF / −1, the device is not acknowledging.

Boot behaviour: power LED lights immediately; chip is asleep (SLEEP = 1) until written; no factory program.

## 6. Real failure modes

| Fault | What physically happens | What the user sees |
|---|---|---|
| Reverse polarity on VCC/GND | No protection diode, no fuse [3]. Current flows backwards through the LDO's internal parasitic/ESD diodes and the MPU-6050's ESD diodes, limited only by the supply **(exact path unverified)**; the MPU's VDD abs min is −0.5 V [1]. A few seconds at 5 V reversed typically kills the LDO (hot, sometimes visibly cracked) and can kill the MPU. | LED dark; LDO hot to the touch; afterwards the board may read nothing or the LDO stays shorted. |
| Over-voltage on VCC | 662K (XC6206) max input 6 V [10] (Torex; 8 V on UMW second source). 7.4-12 V (a 2S LiPo or the Arduino VIN) destroys the LDO; if it fails short, VCC passes straight to the 3.46 V-max MPU-6050 (abs max 6 V) [1] **(failure mode typical, unverified)**. | LDO burns (smell, discoloured), then the MPU dies; I²C scan finds nothing. |
| 5 V straight into the 3.3 V net | Same as a shorted LDO: VDD 5 V is above the 3.46 V operating max but under the 6 V abs max; out-of-spec, may survive briefly **(survival unverified)**. | erratic readings, warm chip. |
| Brown-out | No BOD on the MPU-6050 itself, but it has a power-on reset that needs a monotonic VDD ramp (10-90 % within 100 ms) [1]. A slow or dipping supply can leave it in a bad state; supply below ~2.375 V is out of spec. On the host side the Uno's BOD (2.7 V) resets the AVR. | After a dip, the MPU may return to the power-on state (asleep, ranges reset): data go to zero or scales change silently until the host re-initialises. |
| Over-current | The board draws ~5 mA; nothing on it is a load. A short on VCC_3.3V hits the LDO's current limit **(XC6206 short-circuit protection: unverified)**. Shorting INT or SDA low/high only stresses the pin drivers. | LED dark, LDO warm. |
| Cold solder joint on the header | Header pins are hand-soldered by the user. A dull, balled joint on SDA/SCL makes the bus intermittent. | I²C scan sometimes finds 0x68, sometimes not; readings freeze, the Wire library hangs or returns −1/0xFF bytes; tapping the board changes behaviour. VCC/GND joint: LED flickers. |
| Unsoldered header pushed into a breadboard | No contact at all on some pins. | "No device found" (the commonest beginner failure). |
| 5 V into a 3.3 V pin (AD0, SDA, SCL, INT, XDA, XCL) | 5 V is above VDD + 0.5 = 3.8 V abs max [1]; current flows into the ESD clamp diode to VDD, back-powering the 3.3 V rail. A 4.7 kΩ in series (the pull-ups) limits it to < 0.5 mA, which is usually survivable; a direct 5 V on AD0 (the usual mistake) has no series resistor. | Often still works at first (0x69 answers); possible latent damage, odd currents, the LED may glow with VCC unplugged (back-powering). |
| Shorting 5 V to GND (on the host) | Not the module's fault: the Arduino's USB polyfuse (Uno: 500 mA) trips or the regulator limits. | Arduino resets/disconnects; the GY-521 LED goes out. |
| Forgot to wake the chip | Reset value of PWR_MGMT_1 is 0x40 (asleep) [2]. | all readings 0 (temp reads 36.53 °C) while the scan finds 0x68. |
| Wrong address | AD0 floating on a clone with no pull-down, or tied high. | scan finds 0x69 instead; `begin()` fails at 0x68. |
| Counterfeit / clone chip | Many cheap boards carry remarked or clone ICs whose WHO_AM_I is 0x70 (that is an MPU-6500), 0x72 or 0x98 **(values from community reports: unverified)**. | Adafruit `begin()` returns false ("Failed to find MPU6050 chip") although the scan finds 0x68; Electronic Cats `testConnection()` may fail. |
| Two modules with 2.2 kΩ pull-ups, or 10 modules | Pull-ups in parallel too strong (more than 3 mA sink). | Bus errors, low levels > VIL. |
| Bad capacitor (Playground report) | A wrong/failed REGOUT or CPOUT capacitor | "high noise level" [4] |
| Gyro bias not calibrated | ZRO up to ±20 °/s [1]. | Integrated angle drifts steadily when the board is still. |
| Vibration / motor mount | Accelerometer sees vibration as tilt; above the DLPF band it aliases. | Jittery accel angle; set DLPF 20-44 Hz and soft-mount. |
| Mechanical shock | Abs max 10 000 g for 0.2 ms unpowered [1]; dropping on a hard floor is usually fine. | — |
| ESD | 2 kV HBM [1]. | — |

## 7. Lesson facts

Host: Arduino Nano/Uno (5 V). Wiring: VCC → 5V, GND → GND, SCL → A5, SDA → A4, (INT → D2 for interrupts). Use the GY-521's own pull-ups; no level shifter needed for SDA/SCL (section 3.6).

1. **Find it and wake it (I/O):** I²C scanner, expect 0x68. Read WHO_AM_I (0x75) → 0x68. Then write PWR_MGMT_1 = 0x01 and stream raw counts. Show that the chip at reset reads zeros. Move AD0 to 3.3 V → 0x69 (WHO_AM_I still 0x68).
2. **Gyro rate and drift (sensor):** read GYRO_YOUT (0x45/0x46) / 131.0 → °/s. Integrate `angle += gy * dt` with `dt` from `micros()`. Hold still: drift equals the bias. Then calibrate: average 500 samples at rest, subtract (or `mpu.CalibrateGyro(6)` in Electronic Cats). Drift drops by 1-2 orders of magnitude but never to zero.
3. **Accelerometer tilt:** `pitch = atan2(-ax, sqrt(ay*ay + az*az)) * 180/PI` and `roll = atan2(ay, az) * 180/PI` (aerospace convention, valid to ±90° pitch). The original's `atan2(ax, az)` has the opposite sign and ignores ay, so it only works for rotation about Y alone. Whatever formula is used, the gyro axis and sign must match it (pitch pairs with GYRO_Y, roll with GYRO_X): tilt slowly and check that the integrated gyro angle and the accel angle move the same way, or flip the gyro sign. 57.2958 = 180/π. Show bumps as false tilt. Choose DLPF with `setFilterBandwidth(MPU6050_BAND_21_HZ)` or CONFIG = 4.
4. **Complementary filter:** `angle = alpha * (angle + gyroRate * dt) + (1 - alpha) * accelAngle;` with alpha = 0.98. **Time constant τ = α·dt / (1 − α)**: dt = 10 ms → τ = 0.49 s (crossover f = 1/(2πτ) ≈ 0.32 Hz); dt = 4 ms → 0.196 s. Choose τ first (0.2-1 s) then α = τ / (τ + dt). The gyro is high-passed, the accelerometer low-passed, and they sum to exactly 1, so **a perfect gyro + perfect accel give zero lag**. A gyro bias b leaves a constant offset of **b·τ** (not zero). Better filters: **Kalman filter** (TKJ Electronics "Kalman Filter Library" 1.0.2: `#include <Kalman.h>`, `Kalman k; k.setAngle(accAngle); angle = k.getAngle(accAngle, gyroRate, dt);`, a 2-state angle + gyro-bias filter, so it also estimates the bias), **Madgwick** (gradient-descent AHRS, β gain), **Mahony** (PI complementary on SO(3)), and the chip's own **DMP** (quaternions via `MPU6050_6Axis_MotionApps20.h`). Yaw cannot be corrected without a magnetometer (the gyro-only yaw always drifts).
5. **Protocol extension:** interrupt-driven reads (INT_ENABLE.DATA_RDY_EN = 1, INT → D2, `attachInterrupt(digitalPinToInterrupt(2), isr, RISING)`), sample-rate control (SMPLRT_DIV, 100 Hz with CONFIG = 3, SMPLRT_DIV = 9), FIFO burst reads, or the DMP.

**Fig. 09 synthetic signals, checked against a real filter.** The original draws `filtA(t) = truth(t − 0.06) + 1.2·nz(t)`, which is **not** what a complementary filter produces [12]. I ran the real filter (`angle = 0.98·(angle + gyro·dt) + 0.02·acc`) on the original's own inputs (gyro = d(truth)/dt + 2.4 °/s, acc = truth + 16·nz(t), truth = 8 sin 1.1t + 3 sin 2.7t), from 10 to 60 s (my script, computed):

| dt | α | τ | Mean error (bias offset) | Noise rms | Peak deviation |
|---|---|---|---|---|---|
| 10 ms | 0.98 | 0.49 s | **+1.35°** (b·τ = 1.18°) | **1.48°** | 4.05° |
| 10 ms | 0.99 | 0.99 s | +2.56° | 1.07° | 2.74° |
| 4 ms | 0.98 | 0.196 s | +0.63° | 2.17° | 5.63° |

So a real filter on those signals shows: **no 60 ms lag** (the true motion passes through the gyro path unchanged); a **constant offset of about +1.2-1.4°** from the uncalibrated 2.4 °/s bias; and **low-passed accelerometer noise** of about ±1.5° rms that wanders smoothly (correlated over ~τ), not the original's fresh ±0.6° step every 0.1 s. The rebuild should compute the filter rather than fake it. Also: the original's accel noise (±8° uniform jumps every 100 ms) is far larger than real sensor noise (≈ 0.2° rms at rest); it stands for hand-held bumps, and the lesson should say so. The 2.4 °/s bias is realistic for an uncalibrated part (spec ±20 °/s).

## 8. Internals (see-through view)

- **MPU-6050 package:** 4 × 4 × 0.9 mm QFN, black mould compound over a copper lead frame. Inside, **two dies**: a CMOS ASIC (signal chain, ADCs, DMP, I²C, FIFO, oscillator, charge pump) and a MEMS die bonded **face-to-face on top of it at wafer level** (InvenSense "Nasiri-Fabrication": the MEMS wafer is bonded to the CMOS wafer, which hermetically seals the moving parts) [1][11]. Gold bond wires run from the CMOS die's pads to the 24 lead-frame pads **(wire material unverified; gold is typical)**.
- **Gyroscope:** vibrating proof masses driven into resonance (tens of kHz **(unverified)**); rotation creates a Coriolis force perpendicular to the drive, detected by capacitive comb pick-offs ("teeth" ~1 µm wide on the die photo [11]); then demodulated, filtered, 16-bit ADC [1]. The charge pump (CPOUT, 2.2 nF) makes the high drive voltage (CPOUT abs max 30 V) [1].
- **Accelerometer:** a separate proof mass per axis on springs; displacement changes capacitance [1].
- **No quartz crystal** on the board or in the chip: the clock is an on-chip oscillator / gyro-locked PLL [1].
- **LDO (XC6206):** a single small die in SOT-23: PMOS pass transistor, bandgap reference, error amplifier, current limiter **(block diagram from memory: unverified)**.
- No RF can, no USB bridge, no flash on the board. The DMP firmware lives in the chip's RAM and must be uploaded by the host at each power-up (I2Cdevlib does this, ~1.9 kB) **(size unverified)**.

## 9. Assembly and power-up

- **Manufacture:** all SMD parts (QFN, SOT-23, 0603 passives, case-A tantalum, 0603 LED) are paste-printed and reflowed on one side; the QFN's pads are under the body (no visible solder fillets except at the lead ends). Panels are V-scored/routed apart. The **header is supplied loose** (one straight, one right-angle 1×8) and soldered by the user: it goes on last.
- **Power-up sequence:** VCC applied → LDO output rises → **D1 lights at once** → MPU-6050 power-on reset; registers readable after 20-100 ms [1]; chip is **asleep** (PWR_MGMT_1 = 0x40) and the clock source is the internal 8 MHz oscillator. Nothing streams until the host writes PWR_MGMT_1. No default program, no enumeration.

## 10. Uncertainties

- **LED colour:** no source read states it, and the photographed LED is unlit. Red is assumed (my recollection of these boards, not confirmed); the original sim used green.
- **662K on GY-521:** the 662K = XC6206P332MR identification is confirmed [10], but no measured photo of a 662K GY-521 was found in time; the photographed board has a 5-pin "A249" LDO and 2.2 kΩ pull-ups, and the only schematic shows a 5-pin LDO with 4.7 kΩ pull-ups. Which variant is "most common" today is not established.
- **A249:** the 5-pin LDO on the photographed board was not identified (possibly an LP2985/MIC5205-type 3.3 V LDO) **(unverified)**.
- **Torex XC6206 specs:** 6.0 V, 250 mA (5 V type), 250 mV @ 100 mA come from a datasheet excerpt on a mirror [14], not the Torex PDF (blocked: "Access Denied"). The Iq, pinout and protection features are from memory. The UMW second-source listing gives 8 V / 100 mA / 0.24 V @ 50 mA.
- **Part positions** are from one photograph (±0.3 mm); there is no design file. Fritzing's illustration puts the holes 0.8 mm nearer the edge than the photo.
- **Back-side silkscreen** ("GY-521") not seen.
- **Board thickness** 1.6 mm assumed.
- **TDK official lifecycle status** and named successor not read on tdk.com: the official product URL https://invensense.tdk.com/products/motion-tracking/6-axis/mpu-6050/ now returns "Sorry — we couldn't find the page you were looking for" (consistent with removal, not proof).
- **Datasheet revisions:** read PS Rev 3.1 and RM Rev 4.0, not the final 3.4 / 4.2.
- **Typical (not max) gyro bias** of real units and post-calibration residual are not from a primary source.
- **Clone WHO_AM_I values** (0x70, 0x72, 0x98) are community reports.
